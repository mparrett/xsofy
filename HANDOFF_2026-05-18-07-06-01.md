## Key Decisions

### Architecture choices that shaped this session's work

- **Host bar populates `#shell-bottom`, fetched as `shell.html` sidecar.** The let-go fork's template stays generic — empty slots collapse via `:empty { display: none }`. xsofy ships `dev/shell.html` and the dev-serve dance copies it to `dist/`. Inline `<script>` tags inside the fragment are re-cloned post-injection so they execute (innerHTML doesn't run scripts).

- **Touch input via key synthesis, not `js/recv`.** Initially scoped `js/recv` as required (per yesterday's memory). But the existing SAB key path is already the input channel — a button tap just calls `window._lgKey('h')` and the worker reads the byte out of `term/read-key` like any keystroke. Zero game-side changes; zero new Go primitives. Yesterday's "don't speculatively build js/recv" turned out to be right for a different reason than expected.

- **Layout collapse over responsive `make-world`.** Considered making the world itself smaller on narrow terminals. Rejected — that's a content change (monster placement, room sizing, depth-curve) rather than a layout change. Instead `ui/layout` drops sidebar (when gw < 80) and log (when gh < 16). The HTML bar carries HP/depth/quest, so dropping the sidebar costs nothing under WASM. Status row keeps its 1 row.

- **Player-centered camera via rect attribute.** Map rect grows a `:cx :cy` pair (top-left world coord of the visible window), populated by `with-camera` in `render-full` / `render-dirty` / `animate-vfx!`. Render functions consume the offset through a new `map-cell` helper that translates world (x,y) → terminal [col row] or nil if offscreen. All 9 sites (render-map-tile, render-entity, render-map iteration, render-dirty FOV walks ×3, restore-dirty-cells!, render-vfx-frame ×3) use the same helper — uniform, easy to evolve. Render-dirty force-falls-back to render-map when the camera shifts, since a per-cell dirty pass on a scrolled viewport would leave stale geometry.

- **User-toggleable fontSize, persisted in localStorage.** Started with auto-orientation-driven (22 portrait, 14 landscape). User wanted toggle. Solution: small "A22" chip in info row cycles 14→18→22→28; localStorage key `xsofy/font-size`. First-ever load picks by orientation as a sensible default; once user taps, their choice wins regardless of orientation. Chip uses `pointerdown` like the D-pad does.

- **Wake on resize via BEL.** Game-loop sits parked in `Atomics.wait` inside `term/read-key` — without input it never re-checks `term/size`. Solution: `window._lgWake()` injects BEL (0x07) through the existing sendKey path. parse-key returns `:unknown`, update-world returns world unchanged, but the resize check at the top of the next iteration runs and triggers render-full at the new dims. Called from the window resize listener and `_lgSetFontSize` after `fitAddon.fit()`.

## Gotchas

### Build / serve

- `serve` from Homebrew is v13 and **silently ignores the `headers` block** in `serve.json`. Result: no COI headers, no SAB, `term/read-key` FATALs. Always use `npx --yes serve@latest`. CLAUDE.md is updated to say this.
- `serve.json` now has `"cleanUrls": false`, `"directoryListing": false`, and an explicit `"/" → "/index.html"` rewrite. Without `cleanUrls:false`, `/shell.html` gets rewritten to `/shell` (404). Without `directoryListing:false`, `/` would serve a file index (since `cleanUrls:false` also disables auto-`index.html`). The explicit rewrite restores `/` → `index.html`.
- After `lg -w dist main.lg`, copy *two* sidecars: `cp dev/serve.json dev/shell.html dist/`. The build doesn't touch those files; they need to be re-copied if you `rm -rf dist/`.

### Resize and dimensions

- **FitAddon does not refit cols on viewport resize.** Rows do refit. Cause unknown — possibly a timing issue between the window resize event and the `.xterm` container's layout. Verified via probe: viewport 1280→375 → rows 46→27 (good) but cols stays at 150 (bad). Boot-in-portrait works because FitAddon's first `fit()` runs after the terminal is fully laid out. Workaround: tell users to reload after rotating. Real fix: ResizeObserver on `#terminal`. **This is the #1 candidate for next session.**
- The game-loop only checks `term/size` after `term/read-key` returns. `window._lgWake()` was added to poke a no-op BEL byte so the loop wakes after a resize or font-size change. Without it, you'd need a real keystroke before the layout updated visibly.
- `term.options.fontSize = N; fitAddon.fit()` works correctly (verified font cycle goes 22→28, rows 17→13, game re-renders within ~100ms). The wake mechanism is what makes this feel instant.

### xsofy-specific render quirks

- The map render uses *world coordinates* with the rect's `:cx :cy` offset. Anything that paints into the map rect must use `map-cell` (not raw `(+ (:x r) x)` arithmetic) or the camera won't apply and the paint will land in the wrong place. See `xsofy/render.lg` line ~58 (the `map-cell` helper) for the pattern.
- `render-dirty` is now a two-mode function: cheap per-cell repaint when the camera hasn't shifted, full repaint when it has. Camera shifts whenever the player moves toward a world edge (within `rect.w/2` cells of an edge stops centering; otherwise it tracks). If you add new map rendering, decide which mode your change interacts with.
- `tests/world.lg` has a flaky `(= hp0 hp1)` test that fails roughly 1 in 5 runs — RNG seeds where the player starts on/next-to fire or in a melee-able tile. Pre-existing, not introduced this session. Don't worry about it on a single red run.

### Bridge / globals reference

Globals exposed by the let-go template (defined in worker mode unless noted):

| Global | Purpose | Defined in main-thread mode? |
|---|---|---|
| `_lgEmit(name, dataJson)` | Worker→main relay for `js/emit` events (auto-defined in worker). | n/a — main-thread mode dispatches directly. |
| `_lgKey(str)` | Inject UTF-8 bytes as if typed. Used by shell touch buttons. | No-op + console warn. |
| `_lgSetFontSize(n)` | Change xterm fontSize and refit. Bounded [6, 64]. | Defined top-level, works either mode. |
| `_lgWake()` | Poke BEL into SAB so the game-loop wakes from `read-key`. | No-op. |

`window._lgKeyInt32` and `window._lgKeyUint8` are NOT exposed from the main thread; the SAB references live inside `startWorkerMode`'s closure. Adding them as globals is a 2-line change if a probe needs to inspect SAB state directly.
