## Key Decisions

### Methodology choices that shaped this session

- **Fix the protocol, not the symptom.** When the held-key chug surfaced, the obvious tactical fix was "drop-on-overflow in `sendKey` instead of busy-wait." Cheap, ~3 lines. But the discussion that followed identified three independent design issues stacked on top of each other: buffering, synchronization, and backpressure conflated into one mechanism. We chose the structural fix (ring buffer) over the bandage. Cost was bigger (~50 lines + cross-file constant sync), but the architecture is now correct: producer never blocks the main thread under any input source, and overflow policy becomes a producer-side choice. The bandage would have left us re-architecting later when the next case (chord input, programmatic replay) didn't fit "always drop."

- **Constants mirrored, not generated.** The SAB layout constants (`CAPACITY`, `MAX_KEY_LEN`, byte offsets, Int32 indices) live in both `wasm.go` (JS-side) and `pkg/rt/term_wasm.go` (Go-side) and must stay in sync. Considered generating them from a shared source; rejected — they're protocol constants, change rarely, and a comment cross-referencing the other file is enough. A drift bug would be caught on first invocation.

- **Ring buffer size is 8, not 4 or 16.** With engine sustaining ~24Hz busy / ~80Hz calm and auto-repeat at ~12Hz, the buffer never needs more than 1-2 slots in steady state. 8 gives 4× headroom for bursts (e.g. a triple-tap during animation, or programmatic replay batching). 16 would be wasteful; 4 would fill under noisy timer jitter.

- **`*perf-overlay*` flag lives in `xsofy.render`, not `xsofy.world`.** First instinct was to mirror the placement of `*perf-detail*` (which is in world.lg). But `*perf-detail*` would affect `update-world`'s internal computation; `*perf-overlay*` only affects render. Modules should own their own state. Moved it to render.lg to avoid introducing a new world→render dependency just for one boolean.

- **ms gauge shows previous turn's value (not current).** The render of turn N must run before the timing for turn N can be computed. So the gauge lags by one turn. Acceptable — for human-paced reads, that's invisible. The alternative (render twice per turn — once for visible state, once to update the gauge) doubles render cost for negligible UX gain.

### Known flaky test

`tests/world.lg`'s `(= hp0 hp1)` fails roughly 1 in 5 runs due to RNG-seeded starting positions adjacent to fire/enemies. Re-run `lg tests/run.lg` 2-3 times if it fails after a change; if it consistently fails, the change is probably the cause. Documented in `CLAUDE.md`.

### SAB layout constants must stay in sync

If you ever touch `CAPACITY`, `MAX_KEY_LEN`, offsets, or index positions, update BOTH `let-go/wasm.go` (JS) AND `let-go/pkg/rt/term_wasm.go` (Go) in the same change. There's no enforcement — just a comment cross-referencing the other file. A mismatch will manifest as garbage keystrokes, dropped input, or a SAB out-of-bounds in the worker.

### Go `fmt.Sprintf` and the wasm.go template

The wasm.go HTML template is fed through `fmt.Sprintf` to inject `wasm_exec.js` and the gzipped WASM. Any literal `%` in the template needs to be `%%`. This bit me during the ring-buffer commit — `w % CAPACITY` got eaten and became `%!C(MISSING)APACITY` in the served bundle, blocking page boot with a syntax error. Use `%%` for modulo, percentages, and any other `%` in template content.

### Engine ceiling vs auto-repeat cadence

- Engine busy-state median: ~41ms/turn → 24Hz ceiling
- Engine calm-state median: ~12ms/turn → 80Hz ceiling
- Current auto-repeat: 12Hz (150ms initial, 83ms interval)

If you bump `REPEAT_INTERVAL` lower, you stay smooth up to engine busy ceiling (24Hz); past that, the ring buffer absorbs the burst and excess `sendKey` calls return `false` (silent drop). Don't try to outrun the engine — there's nothing to gain visually above the ceiling.

### The ms gauge needs `:perf-ms` on the world

Lives at `xsofy.render/render-perf-overlay`. Reads `(:perf-ms world)`. If `main.lg`'s `:game` branch ever changes its post-render path and forgets to assoc `:perf-ms` on the recurred world, the gauge silently disappears. (It no-ops when missing — by design — but that "did the gauge stop showing?" debugging moment is real.)
