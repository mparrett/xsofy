A stranger filed a bug we'd already cured. The cure lived in a fork thick with unrelated work — a bottom-bar shell, a touch D-pad, a perf-detail channel — none of it the bug's business. The story of this evening is the discipline of pulling exactly two commits out of that thicket and walking them, alone, to the door.

Act I ᚱ

The echo from elsewhere — a bug we already cured, returning from the wild

nooga/xsofy#3 arrived in plain language: "flashes between this error and 'loading' rapidly", with a screenshot of the Interactive Input Unavailable panel on Android Firefox. A second comment confirmed the same on macOS Safari.

We knew this one. Two days earlier our own docs/project_notes/bugs.md had recorded it chapter-and-verse: the SW shim setting Cross-Origin-Embedder-Policy: credentialless (Chrome-only), the bootstrap doing register().then(location.reload()) with no loop guard. Together: Safari rejects the header → isolation never activates → reload forever. The previous quest log called it Coils of Isolation.

We had the fix in our let-go fork — two commits on expmt/js-bridge, layered under months of work that had nothing to do with COI. The trick was extracting them cleanly and proving the extraction was correct.

Act II ᛗ

Triage before code — a ticket, a map, and a list of what not to bundle

Before any branching, we wrote docs/project_incoming/issue_3.md — a ticket to ourselves answering three questions: which repos need changes, what the minimal diff looks like, and what tangential improvements we'd be tempted to smuggle in.

Answers came out cleaner than expected. nooga/xsofy's dist/ is .gitignored; its deploy workflow runs go install github.com/nooga/let-go@latest on every push to main. The moment a fix lands upstream and tags, the next xsofy build picks it up automatically. No xsofy PR is needed. The fix is entirely a let-go change — specifically to wasm.go, the template that generates the boot HTML and the SW shim.

The minimal PR turned out to be two commits we already had: f3ed218 (loop guard + auto-unregister-when-isolated) and 44812e9 (pass-through server headers + use require-corp instead of credentialless). Together: one file, +28/-4. Anything more — the viewport meta commit, the bridge primitives, the shell-slot scaffolding, the perf telemetry — was a separate story for a separate PR.

The hardest part of contributing upstream isn't writing the patch. It's resisting the bundle. Every adjacent improvement you'd like to ship is a knock against the patch's chance of being merged quickly.

Act III ᛒ

The fork and the cherry-pick — two commits, no drift, clean apply

An exploratory pass against origin/main in let-go confirmed what we'd hoped: the surrounding context for both commits was byte-identical between upstream and our pre-fix state. No reconciliation, no manual patch reconstruction.

$ gh repo fork nooga/let-go --remote --remote-name=fork --clone=false https://github.com/mparrett/let-go $ git -C let-go fetch origin --quiet $ git -C let-go checkout -b fix/coi-bootstrap-safari-firefox origin/main $ git -C let-go cherry-pick f3ed218 44812e9 [fix/...] 0e0385f fix: guard COI service worker against reload loops [fix/...] 891cc62 fix: COI service worker passes through server headers $ git -C let-go diff --stat origin/main wasm.go | 32 ++++++++++++++++++++++++++++---- 1 file changed, 28 insertions(+), 4 deletions(-)

Two commits, conceptually distinct (HTML loop guard vs SW header policy), preserved as a pair so reviewers can read each intent independently. If nooga prefers a single commit, "Squash and merge" in the GitHub UI handles it without us rewriting history.

Act IV ᛇ

The mirror that flattered us — a first verify pass that didn't actually verify anything

For verification, the first instinct was to build from our daily branch — expmt/js-bridge in let-go, which has the COI fix baked in alongside everything else — rebuild xsofy's dist/, serve it on :8001 with dev/serve.json sending the isolation headers, and load it in Chrome.

It loaded. It looked great. There was a D-pad on the bottom. The info row showed HP and turn count. The page isolated immediately and the title scrolled in.

None of those things exist in upstream xsofy. The build on :8001 wasn't a test of the PR; it was a test of our fork, which we'd been running variants of for two days. A test that doesn't isolate the variable under test isn't a test. It's reassurance.

You can pass a hundred dailies and still ship a regression. What proves an upstream change is a build that resembles upstream — not the one you've been polishing on your own screen.

Act V ᛈ

The module proxy trap — why lg -w built the runtime from the wrong source

A first attempt to build with a binary off the new fix/coi-bootstrap-safari-firefox branch failed at compile-time: Can't resolve js/emit. The bridge primitive that xsofy's ui_bridge.lg depends on doesn't exist on origin/main. Expected; that's why this exact build will be the one the upstream PR delivers, where xsofy has no bridge references either.

The trickier discovery came on the next attempt. Building from expmt/js-bridge — the branch that does have the bridge primitive — produced a WASM bundle that compiled fine but threw at runtime:

TypeError: nil is not a function :data {:trace ("new-game" "emit-boot" "<unknown>")}

A clue had been hiding in the build log: go: added github.com/nooga/let-go v1.7.4. lg -w generates a small Go module that imports github.com/nooga/let-go and go builds it. By default that fetches let-go from the public module proxy — which only knows the published upstream tags. Our local bridge code in pkg/rt/js_wasm.go was invisible to the build. The .lg compiler (run from our local checkout) happily resolved js/emit to a placeholder; the WASM runtime (built from upstream v1.7.4) had no such primitive registered. At runtime, the bridge chain collapsed to nil.

The fix was a single environment variable. lg's WASM bootstrap accepts LETGO_SRC as an explicit path to a local let-go source tree; when set, it writes a replace directive into the generated go.mod instead of fetching from the proxy.

$ LETGO_SRC=/Users/matt/projects-new/3p/let-go \ /tmp/lg-coi-min -w dist main.lg resolving dependencies... building wasm... output: dist/index.html (6.3 MB)

Worth knowing for the future. lg -w tries to find local source automatically (walks the cwd, then walks from the executable's directory), but a binary living in /tmp/ with a cwd outside the let-go tree satisfies neither walk. LETGO_SRC is the unambiguous override.

Act VI ᛚ

The clean worktree — stock xsofy, minimal let-go, no serve.json

With the build pipeline understood, we set up the verification stack that actually resembled what the upstream PR would deliver. Two parallel branches: a binary built from fix/coi-bootstrap-safari-firefox (the PR branch itself, two commits off origin/main), and a clean checkout of stock upstream xsofy via a temporary git worktree.

$ git -C let-go switch fix/coi-bootstrap-safari-firefox $ cd let-go && go build -o /tmp/lg-coi-min . $ git -C xsofy worktree add /tmp/xsofy-upstream origin/main $ cd /tmp/xsofy-upstream $ LETGO_SRC=~/projects-new/3p/let-go /tmp/lg-coi-min -w dist main.lg $ ls dist/ coi-serviceworker.js index.html

Two files. No shell.html, no serve.json, no bridge consumer code, no D-pad. Exactly what an upstream user gets when they hit the next GitHub Pages deploy.

The other half of the trick was how we served it. The dev path uses dev/serve.json to inject COOP/COEP at the server layer — that's what makes the local SAB story painless. GitHub Pages does not send those headers. To replicate the production scenario, the dev server must stay quiet, and the SW shim has to do all the isolation work itself. So: npx serve dist -l 8002 --ssl-cert ... --ssl-key ... with no serve.json present. A curl against :8002 returns 200 OK with no Cross-Origin-* headers at all. The SW is the entire mechanism under test.

Worktrees were exactly the right tool here. Two clean checkouts of the same repo at different revisions, side by side, no stashing, no branch hopping. The /tmp/xsofy-upstream worktree existed for the length of one verification and was removed at the end.

Act VII ᛟ

The crossing — observation, push, PR

On both Chrome (macOS) and iOS Safari the sequence ran cleanly:

  1. First load — crossOriginIsolated is false; the bootstrap registers the SW, sets the _lgCoiTried loop guard, and reloads.
  2. A brief flash of Interactive Input Unavailable — the very error message this fix exists to suppress, here showing for the half-second between first paint and reload.
  3. Post-reload — the SW injects require-corp + same-origin; crossOriginIsolated is true; the WASM boots; the title screen rolls.

The brief flash isn't a regression — it's the expected single-shot register-then-isolate sequence, gated by sessionStorage._lgCoiTried so it can never become a loop again. macOS Firefox confirmed the same path. Three browsers, three clean boots.

$ git -C let-go push -u fork fix/coi-bootstrap-safari-firefox remote: Create a pull request for 'fix/coi-bootstrap-safari-firefox' on GitHub by visiting: remote: https://github.com/mparrett/let-go/pull/new/fix/coi-bootstrap-safari-firefox To https://github.com/mparrett/let-go.git * [new branch] fix/coi-bootstrap-safari-firefox -> fix/coi-bootstrap-safari-firefox

The PR opened the next morning, body cribbed from the draft left in the plan file: cause-and-fix table, browser-compat matrix for credentialless vs require-corp, the recovery note for clients still running the old SW. Total elapsed clock time from issue read to PR open: about ninety minutes of focused work plus a night's sleep.

What we learned (or re-learned)

Most of this evening was discipline, not discovery. The fix already existed; the proof of its minimality was the work. The interesting bits were the small misroutes between "I have a patch" and "I have a patch I can defend."

  1. The patch is the easy half. Isolating it cleanly from your daily build — without smuggling in the adjacent improvements you'd love to ship at the same time — is most of the contribution.
  2. Don't trust your daily build to verify an upstream change. Build the minimal stack: a fresh binary off the PR branch, a worktree off upstream main, no dev-only conveniences in the serve path. If your test environment doesn't resemble the real one, your test result doesn't mean what you think it does.
  3. The Go module proxy ships what's published, not what's checked out. When lg -w can't find local source, it fetches from the proxy and your unpushed changes vanish from the build silently. LETGO_SRC is the explicit override; reach for it whenever the binary lives outside the source tree.
  4. Match the production scenario, not the convenient one. GitHub Pages doesn't send COI headers; serving locally with serve.json bypasses the exact code path the bug report targets. Drop the convenience and prove the SW shim alone is enough.
  5. Resist the bundle. Two commits, one file, one concern. The viewport fix, the bridge primitive, the perf telemetry — each is its own PR if it's worth one. Surgical PRs read faster, merge faster, and revert cleaner.
