## Key Decisions

### Architecture choices that shaped the work

- **Server-side COOP/COEP over service-worker shim.** The bundled `coi-serviceworker.js` is fragile (Safari rejects `credentialless`, no loop guard, old SWs poison new clients). `dev/serve.json` sends the headers directly. Commit `6a25330`. Full diagnosis in `docs/project_notes/bugs.md`.

- **Real `test` namespace over hand-rolled harness.** Initially misdiagnosed `clojure.test` as broken; turned out the namespace is `test` (not `clojure.test`) and the macros need `(:require [test :refer :all])` for the `set!` of dynamic vars to resolve across namespaces. Logged in `bugs.md`. Commit `d016e38`.

- **Fork let-go rather than ANSI side-band hack.** User chose the principled path for the dual-UI work. Result: ~140 lines of new code, two clean files in `pkg/rt/`, no VM changes. End-to-end proven via Playwright.

- **`(js/emit ...)` is the only outbound primitive.** Deep interface in Ousterhout terms: one function name hides JSON marshaling, CustomEvent construction, worker-side postMessage relay, and mode dispatch (worker vs main-thread). Native build no-ops after the same arg validation. See `pkg/rt/js.go` for the shared validation and `pkg/rt/js_wasm.go` for the WASM dispatch.

- **`xsofy.ui-bridge` wraps `js/emit`** to auto-namespace events under `:xsofy/` and centralize channel names. New channels are one-line helpers in `xsofy/ui_bridge.lg`. Game code uses `bridge/emit-*` not raw `js/emit`.

- **Mobile portrait first.** Implications for any HTML host: top/bottom bars, not sidebars. Memory: `project_ui_constraints.md`.

## Gotchas

### Build / serve

- `lg -w dist main.lg` MUST be run from the xsofy repo root. Running from a parent directory fails with `Can't resolve world/log-msg in this context` because let-go's namespace resolver uses cwd-relative paths.
- `dist/`, `dist-fork/`, `main.lgb` are gitignored. Don't commit them. They get rebuilt freely.
- After each `lg -w dist main.lg` the `dist/index.html` is overwritten, but `dist/serve.json` is NOT (build doesn't touch it). The `serve.json` was copied/written manually and stays put. If you ever blow away `dist/` entirely, restore `serve.json` from the canonical copy at `dev/serve.json`.

- Their version strings are your "which one am I running" tell. Don't replace brew's — keep both.

### let-go quirks

- A `.lg` file with `(ns ...)` runs **twice** when given to `lg` directly (once as a script, once as a namespace load). The xsofy test runner at `tests/run.lg` deliberately has no `(ns ...)` to avoid double-execution. Same will apply to any new entry-point scripts.
- Macros do **not** auto-resolve symbols across namespaces. If you write a macro in ns A that references a function `f`, callers in ns B can only use it if they either `:refer` it or the macro body uses the fully-qualified `A/f`. Documented in `bugs.md` from the test harness misdiagnosis.
- `(require '(foo))` fails — `require` expects a symbol or vector, not a list. Use `(require 'foo)` or `(require '[foo :as f])`.

### Bridge specifics

- `(bridge/emit ...)` is **silently no-op on native** by design. If you're running `lg main.lg` in a terminal and don't see your events firing, that's expected — they only flow when running under WASM in the host page.
- The bridge currently works only in **worker mode** (cross-origin-isolated). Main-thread-mode would dispatch directly to `window` but the bundle locks into mode at first load. Since `dev/serve.json` enables COI on first byte, worker mode is the practical default.
- New emit channels: add a one-liner in `xsofy/ui_bridge.lg`, not raw `(js/emit ...)` at the call site. The bridge file is the registry of channels.
- Don't speculatively implement `js/recv`. Wait for an actual inbound need.
